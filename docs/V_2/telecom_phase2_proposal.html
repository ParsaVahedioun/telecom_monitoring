خلاصهٔ اجرایی

در فاز دوم، صفحات مدیریتی و صفحهٔ جزئیات پهنای‌باند بازطراحی شد، محاسبات نرخ به‌صورت استاندارد (بر پایهٔ شمارنده‌های SNMP) پیاده‌سازی و اندپوینت‌های API ارتقا یافت. همچنین بهبودهای دیتابیسی (ایندکس‌ها و فیلدهای کمکی) اعمال و خروجی‌گیری اکسل/CSV اضافه شد.

۱) صفحات مدیریت و پهنای‌باند

۱.۱) داشبورد ادمین /admin

  • شاخص‌ها (KPI): کل کاربران، کاربران فعال، میانگین پهنای‌باند کاربران (Avg bps)، بیشینهٔ میانگین پنجره‌ای بین کاربران.
  • نمودارها: رنکینگ مصرف، دونات فعال/غیرفعال، هیستوگرام Avg bps، سری زمانی مصرف کل (Bytes)، نقشهٔ حرارتی موقعیت کاربران، ثبت‌نام‌های ماهانه.
  • اکشن‌ها: لینک «جزئیات» هر کاربر، خروجی CSV/XLSX با پارامترهای hours و window_seconds.

۱.۲) صفحهٔ جزئیات پهنای‌باند /admin/user-bandwidth

  • فیلترها: بازه‌های آماده (۱/۶/۱۲/۲۴ ساعت) + بازهٔ سفارشی، پنجرهٔ تجمیع ۱/۵/۱۰/۳۰ دقیقه، به‌روزرسانی خودکار.
  • KPIها: سرعت لحظه‌ای RX/TX، میانگین RX/TX، «پیک پنجره‌ای» و «کمینهٔ پنجره‌ای» با بازهٔ زمانی، بیشینه/کمینهٔ نقطه‌ای با زمان وقوع.
  • نمودارها: خطی RX/TX/Total (bps) و دونات نسبت RX/TX.
  • جدول خام آخرین ۲۰۰ نمونهٔ نرخ + خروجی CSV/XLSX (SheetJS).

۲) فرمول‌های محاسبهٔ پهنای‌باند

پایهٔ محاسبه، اختلاف شمارنده‌های تجمیعی SNMP برای یک اینترفیس کاربر است (ifHCInOctets/ifHCOutOctets یا معادل):

Δt   = t[i] - t[i-1]           # ثانیه
Δrx  = rx_bytes[i] - rx_bytes[i-1]
Δtx  = tx_bytes[i] - tx_bytes[i-1]

# اگر Δrx یا Δtx < 0 ⇒ ریست/overflow کانتر ⇒ نادیده بگیر
rx_bps    = (Δrx * 8) / Δt
tx_bps    = (Δtx * 8) / Δt
total_bps = rx_bps + tx_bps

۲.۱) تعاریف کلیدی

  • سرعت لحظه‌ای: آخرین نقطهٔ محاسبه‌شده از سری bps (بین دو نمونهٔ اخیر).
  • حداکثر/حداقل نقطه‌ای: بیشینه/کمینهٔ total_bps (برای کمینه بهتر است صفرهای نویزی حذف شوند).
  • پنجرهٔ تجمیع: باکت‌بندی سری بر اساس window_seconds و محاسبهٔ میانگین در هر باکت.
  • پیک پنجره‌ای: پنجره‌ای که میانگین total_bps آن بیشترین است (با window_start/window_end).
  • کمینهٔ پنجره‌ای: پنجره با کمترین میانگین total_bps.
  • آمار کلی: avg، p95، max روی سری total_bps.

۲.۲) توصیه‌ها

  • Sampling یکنواخت (۳۰–۶۰ ثانیه)؛ هم‌زمان‌سازی ساعت‌ها (UTC/NTP).
  • استفاده از کانترهای ۶۴ بیتی (HC) برای جلوگیری از overflow.
  • فیلتر outlier برای Δt بسیار کوچک/بزرگ یا جهش‌های غیرعادی.

۳) ارتقای دیتابیس

۳.۱) فیلدها و ایندکس‌ها

  • users: افزودن created_at (UTC)، ایندکس is_active، فیلدهای اختیاری region/lat/long.
  • traffic_logs: ایندکس ترکیبی (user_id, timestamp) برای گزارش‌گیری سریع.
# Alembic (خلاصه)
def upgrade():
    op.add_column('users', sa.Column('created_at', sa.DateTime(timezone=True), server_default=sa.func.now()))
    op.create_index('ix_users_is_active', 'users', ['is_active'])
    op.create_index('ix_traffic_logs_user_time', 'traffic_logs', ['user_id','timestamp'])

def downgrade():
    op.drop_index('ix_traffic_logs_user_time', table_name='traffic_logs')
    op.drop_index('ix_users_is_active', table_name='users')
    op.drop_column('users', 'created_at')

۳.۲) مقیاس‌پذیری

  • در حجم بالا: جدول‌های پیش‌تجمیع (۱m/۵m/۱۰m) با job زمان‌بندی‌شده.
  • در Postgres: پارتیشن‌بندی زمانی برای traffic_logs.

۵) بهبودها و رفع باگ‌ها

  • رفع 404 صفحهٔ جزئیات با افزودن مسیر /admin/user-bandwidth (و alias اختیاری).
  • همخوانی با Python 3.13: جایگزینی/ارتقای کلاینت SNMP (پرهیز از پکیج‌هایی که به imp وابسته‌اند).
  • فیلتر Δ منفی (overflow/reset) در محاسبات؛ حذف outlierهای زمانی.
  • افزودن فیلتر بازهٔ زمانی و پنجرهٔ تجمیع در UI کاربر.
  • افزودن خروجی CSV/XLSX (سمت کلاینت برای صفحهٔ کاربر، و سمت سرور برای خلاصهٔ داشبورد).

۶) تست و اعتبارسنجی

  • تطبیق نرخ‌های محاسبه‌شده با دادهٔ خام SNMP و بررسی انطباق زمانی.
  • یکنواختی Sampling و صحت ساعت‌ها (UTC/NTP)؛ استفاده از HC counters.
  • اعتبارسنجی خروجی فایل‌ها در اکسل/LibreOffice.

۷) نقشهٔ راه پیشنهادی

  • Pre-aggregation job (۱m/۵m/۱۰m) و جداسازی storage گرم/سرد.
  • Threshold/Alerting (مثلاً بیش از p95 × 1.5 به‌مدت N دقیقه).
  • Role-based Access، Audit log، Token-based API.
  • کاوش عمیق‌تر per-protocol (NetFlow/sFlow، در صورت نیاز).
